--------------------------------------------------------------------------------
 1. 프로젝트 개요
--------------------------------------------------------------------------------
가지고 있는 옷을 기록하고, 서울의 현재 날씨와 색조합 점수로 코디를 추천하는 웹앱.

- 프런트엔드 : HTML, CSS, JavaScript (빌드 도구 없음, public/ 폴더)
- 백엔드     : Node.js + Express (lib/app.js)
- 데이터베이스: Neon PostgreSQL (@neondatabase/serverless 드라이버)
- 날씨       : OpenWeatherMap 현재 날씨 API (서버에서만 호출, 10분 캐시)
- 배포       : GitHub → Vercel (main 브랜치에 push하면 자동 배포)

로컬 실행
  npm install
  cp .env.example .env      # DATABASE_URL, WEATHER_API_KEY 입력
  npm run dev               # http://localhost:3000
  npm test                  # 단위 테스트 (현재 12개)

환경변수
  DATABASE_URL     (필수) Neon 연결 문자열
  WEATHER_API_KEY  (필수) OpenWeatherMap API 키
  SESSION_SECRET   (선택) 로그인 세션 서명 키. 비우면 DATABASE_URL에서 만들어 씀
  ※ Vercel은 환경변수를 바꾼 뒤 반드시 재배포해야 적용됩니다.

public/js/app.js      화면 동작 전체

test/*.test.js        node:test 단위 테스트
stitch-export/        디자인 원본 (Stitch 목업 5장 + DESIGN.md)


--------------------------------------------------------------------------------
 3. 데이터베이스
--------------------------------------------------------------------------------
closets          id, code(아이디, 소문자, UNIQUE), password_hash, created_at
clothes          id, closet_id, name, category(top/bottom/outer/shoes), color_hex,
                 thickness(thin/medium/thick, 신발은 NULL), memo, created_at
clothing_photos  clothing_id(PK, 옷 삭제 시 함께 삭제), mime, data(BYTEA), updated_at
outfits          id, closet_id, top_id, bottom_id, outer_id, shoes_id, temperature,
                 reason, name, created_at

변경 SQL (이미 로컬 .env에 연결된 Neon DB에는 모두 적용됨)
  002_add_password.sql             closets.password_hash 추가
  003_add_clothing_photos.sql      clothing_photos 테이블 추가
  004_add_outfit_name.sql          outfits.name 추가
  005_shoes_without_thickness.sql  thickness NULL 허용 + 종류별 CHECK, 기존 신발 두께 비움
  ※ Vercel이 다른 DB를 쓴다면 그 DB에서 위 파일을 번호 순서대로 실행해야 합니다.

  요청: 비밀번호 3~20자, 영문·숫자·특수문자 1개 이상, 대소문자 구분.

    ※ "영문, 숫자, 1개 이상의 특수문자"를 세 종류 모두 필수로 해석함.
  - 비밀번호는 scrypt 해시로만 저장(평문 저장 안 함).
  - 로그인 유지: 서버가 HMAC으로 서명한 HttpOnly 세션 쿠키(closet_session, 30일,
    SameSite=Lax, HTTPS에서 Secure). 비밀번호가 바뀌면 기존 세션 무효.
  - 로그인 실패 시 아이디/비밀번호 중 무엇이 틀렸는지 구분하지 않음.
  - 로그인 화면: 로그인 / 새 옷장 만들기 탭, 비밀번호 확인, 규칙 실시간 표시,
    비밀번호 보기 버튼.
  - 비밀번호 기능 전에 만든 옷장은 첫 로그인 때 입력한 비밀번호로 설정됨.
  - API: POST /api/closets(가입), POST /api/session(로그인), DELETE /api/session(로그아웃)
  - DB: 002_add_password.sql

  - 저장한 코디에서 지우면 다시 저장 가능. 어제 저장한 조합은 오늘 다시 저장 가능.
  - 같은 날 같은 조합을 다시 저장하면 새로 만들지 않고 기존 코디 반환(duplicate).
  - 날짜 기준: Asia/Seoul 자정.

[15] 추천 동작 방식 문의                                  (코드 변경 없음)
  - 추천은 매번 그 자리에서 계산하며 무작위 요소가 없음. 기온 구간이나 옷장이
    바뀌지 않으면 같은 TOP 3가 나옴. 하루 동안 고정되는 것은 아님.

[16] 랜덤 코디 섹션 추가                                  커밋 cc925ec (2026-10-21)
  요청: 오늘의 코디에 규칙을 전혀 따르지 않는 네 번째 랜덤 코디. 저장 규칙은 동일.
  구현:
  - 옷장 전체에서 상의·하의·아우터·신발을 하나씩 무작위로 고름(기온·두께·색조합
    무시). 아우터·신발이 없으면 빼고, 상의·하의가 없으면 안내 문구.
  - "다시 뽑기"로 새 조합(가능하면 직전과 다른 조합). 탭을 옮겨도 보던 랜덤 코디
    유지(페이지를 새로고침하면 새로 뽑음).
  - 조화 점수 대신 RANDOM 표시. 랜덤으로 저장한 코디에도 RANDOM 표시.
  - 저장 규칙은 TOP 3와 동일('저장됨' 유지, 같은 날 중복 저장 방지).
  - API: GET /api/recommendations 응답에 random 추가(?random=조합키로 유지),
         GET /api/recommendations/random(?exclude=조합키)
  - 추천 카드 마크업을 lookCard()로 분리해 TOP 3와 랜덤 코디에서 공용.

 5. API 요약
--------------------------------------------------------------------------------
POST   /api/closets                 회원가입 {id, password} (아이디 중복 시 409)
POST   /api/session                 로그인 {id, password}
DELETE /api/session                 로그아웃
GET    /api/closets/me              로그인한 아이디 확인
GET    /api/clothes                 옷 목록 (?category=&color=)
POST   /api/clothes                 옷 등록
PUT    /api/clothes/:id             옷 수정
DELETE /api/clothes/:id             옷 삭제 (저장 코디에서 쓰이면 409, ?force=1로 함께 삭제)
PUT    /api/clothes/:id/photo       사진 올리기 (JPG/PNG/WebP 바이트, 3MB 이하)
GET    /api/clothes/:id/photo       사진 보기
DELETE /api/clothes/:id/photo       사진 삭제
GET    /api/weather                 서울 현재 날씨
GET    /api/recommendations         TOP 3 + 랜덤 코디
GET    /api/recommendations/random  랜덤 코디 다시 뽑기
GET    /api/outfits                 저장한 코디 목록
POST   /api/outfits                 코디 저장 (같은 날 같은 조합이면 기존 코디 반환)
PATCH  /api/outfits/:id             코디 이름 짓기 {name}
DELETE /api/outfits/:id             저장한 코디 삭제
※ 가입·로그인을 제외한 모든 API는 세션 쿠키로 본인 옷장만 다룹니다.

 6. 알아 둘 점 · 남은 과제
--------------------------------------------------------------------------------
- 저장소가 공개(PUBLIC) 상태. 비밀 값은 없지만 코드는 누구나 볼 수 있음.
- 로그인 실패 제한이 없고 비밀번호 최소 길이가 3자라 대입 공격에 약함.
- Vercel 브랜치 미리보기 주소는 배포 보호가 걸려 있어 외부 사용자가 접근 불가.
  공유는 프로덕션 주소로.
- 커밋 작성자 이메일이 이 Mac의 기본값(…@gimgibeom-ui-MacBookPro.local)으로 기록됨.
  GitHub 계정과 연결하려면 git config user.email 설정 필요.
- 사진은 Neon DB에 저장하므로 사진이 많아지면 DB 용량을 확인할 것.
- 추천 조합 수는 상의×하의×아우터×신발로 늘어나므로, 옷이 아주 많아지면
  추천 계산이 느려질 수 있음.
